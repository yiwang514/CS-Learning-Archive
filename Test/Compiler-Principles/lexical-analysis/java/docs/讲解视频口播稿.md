### 1:20 到 2:20 整体流程

【操作】

打开 `Pl0Lexer.java`，停留在类最上方的注释和方法声明区域。可以画出或指着手说明调用顺序。

```text
main -> run -> getsym -> getch
```

【口播】

```text
整个程序可以分成四层。

main 负责取得源文件名。

run 负责打开文件、反复调用 getsym，最后打印 Token 表。

getsym 负责识别一个完整单词，也就是一个 Token。

getch 负责取得下一个字符，它不理解 Token，只负责字符流动。
```

【口播】

```text
可以把程序理解成两条线。

第一条是字符流：readNextLine 每次读一行，getch 每次从当前行取一个字符。

第二条是 Token 流：getsym 根据当前字符判断它是关键字、标识符、整数还是特殊符号，然后交给具体的识别函数处理。

最后 recordCurrentToken 把识别结果加入 Token 列表，printTokens 统一打印。
```

【必须讲的代码】

定位到：

```java
while (currentSymbol != Symbol.PERIOD && getsym()) {
}
```

【口播】

```text
这里有两个结束条件，用 && 连接。

第一，当前符号已经变成句号 PERIOD，说明程序结束。

第二，getsym 返回 false，说明文件结束或者读取失败。

因为 Java 的 && 会短路，如果当前符号已经是句号，后面的 getsym 就不会继续调用。
```

【速记】

```text
句号：PL/0 程序结束
getsym：成功得到一个 Token
```

### 2:20 到 3:20 关键数据结构

【操作】

停留在 `Symbol`、`TokenCategory` 和 `Token` 三个定义上。不要展开所有枚举。

【口播】

```text
Symbol 枚举保存程序内部的符号种类，例如 CONSTSYM、IDENT、NUMBER、READSYM、WRITESYM、NEQ。

TokenCategory 枚举保存 Token 表的分类，例如 KEYWORD、IDENTIFIER、INTEGER、SPECIAL 和 ERROR。

Token 类把三项内容放在一起：word、category、value。

【口播】

程序还用两个 Map 做查找。

keywords 负责把 begin、const、read、write 这样的字符串转换成对应的 Symbol。

specialCharacters 负责把加号、等号、分号这样的单字符转换成特殊符号。

这样识别出一个单词后，不需要写一长串 if，只需要查表。
```

### 3:20 到 5:00 字符读取：`getch()` 和 `readNextLine()`

【操作】

定位到：

```java
private int getch()
```

【口播】

```text
getch 是整个词法分析器的字符入口。

它返回 0 表示成功读取一个字符，返回 -1 表示文件已经结束。

这里不直接返回 char，是因为 char 没有办法自然地表示文件结束。返回 int 以后，上层就可以统一判断 getch 是否等于 -1。
```

【重点条件】

定位到：

```java
if (currentColumn >= currentLine.length()) {
    if (!readNextLine()) {
        return -1;
    }
}
```

【口播】

```text
currentColumn 表示当前读到第几个字符，currentLine.length 表示当前行的长度。

如果当前位置已经到达或者超过行尾，说明这一行读完了，就需要调用 readNextLine 读取下一行。

这里用 >=，而不是 ==，是为了避免索引意外超过长度时继续访问不存在的字符。
```

【重点条件】

定位到 `readNextLine()` 中：

```java
if (inputFinished) {
...
}

if (line == null) {
...
}
```

【口播】

```text
inputFinished 表示之前已经发现文件结束，不能重复读取。

Java 的 readLine 方法读到文件末尾时返回 null，所以这里用 line == null 判断 EOF。

读取失败时，程序不会直接崩溃，而是输出 Can't open file 或 Read file failed 这样的提示。
```

【详略提醒】

readNextLine 中不需要逐行解释 StringBuilder、编码格式和每一个异常。只要讲清楚读一行、行尾补空格、EOF 返回 null 即可。

### 5:00 到 7:00 Token 识别：`getsym()`

【操作】

定位到 `getsym()`。重点指出两个层次：

1. 先跳过空白和注释。
2. 再根据首字符决定 Token 类型。

【口播】

```text
getsym 是整个词法分析器的调度中心。

它不停地做三件事：跳过空白、判断是不是注释、根据当前字符选择具体识别函数。
```

【重点条件】

定位到：

```java
while (true) {
    skipWhitespace();
    if (inputFinished) {
        return false;
    }
    if (currentChar != '/') {
        break;
    }
```

【口播】

```text
这个 while(true) 表示先不断跳过空白和注释，直到遇到真正可以识别的字符。

如果 inputFinished 为 true，说明文件已经结束，返回 false。

如果当前字符不是斜杠，就不是除号或注释，直接跳出循环，进入 Token 分类。
```

【重点条件】

定位到：

```java
if (isLowercaseLetter(currentChar)) {
    readIdentifier();
} else if (isDigit(currentChar)) {
    readNumber();
} else if (currentChar == ':') {
    tokenReady = readBecomes();
} else if (currentChar == '<') {
    tokenReady = readLessOperator();
} else if (currentChar == '>') {
    tokenReady = readGreaterOperator();
} else {
    tokenReady = readSingleSpecialCharacter();
}
```

【口播】

```text
这里按照首字符判断 Token 类型。

小写字母开头就读取标识符，读取完成后再查关键字表。

数字开头就读取整数。

冒号、小于号和大于号需要继续看第二个字符，因为它们分别可能组成 :=、<= 和 >=。

其他符号交给 readSingleSpecialCharacter，通过特殊字符表判断是否合法。
```

【重点条件】

定位到：

```java
if (tokenReady) {
    recordCurrentToken();
}
return tokenReady || !inputFinished;
```

【口播】

```text
只有 tokenReady 为 true 时，才把当前符号加入 Token 表。

原因是有一些情况只产生错误记录，不一定产生正常 Token，例如单独出现的冒号。

返回时写 tokenReady || !inputFinished，表示只要已经得到 Token，或者文件还没有结束，就继续处理。

如果文件结束并且没有 Token，就停止。
```

【详略提醒】

这里不要逐个展开 readLessOperator、readGreaterOperator、isDigit 的每一行。可以一句话说明它们只是完成对应的字符范围判断。

## 5. 录制时的讲话技巧

### 5.1 先讲“为什么”，再讲“是什么”

不好：

```text
这里是 if，判断 currentColumn 是否大于等于当前行长度。
```

更好：

```text
这里判断当前行有没有读完。如果读完，就读取下一行，否则继续从当前行取字符。
```

老师更关心你理解程序流程，而不是你把代码逐字念出来。

### 5.2 每个函数只讲一个核心句

例如：

```text
getch 负责拿一个字符。
getsym 负责判断这个字符开始的是什么 Token。
readIdentifier 负责把连续字母和数字组成标识符或关键字。
readNumber 负责把连续数字组成整数。
skipComment 负责跳过 /* ... */。
error 负责输出教材式错误位置。
```

只有核心函数和关键条件需要多讲，辅助函数可以一句话带过。

### 5.3 演示时不要读完整张表

Token 表可能很长。只需要指出：

```text
关键字
标识符
整数
特殊符号
错误 Token
```

每种选一个代表即可。

### 5.4 切换窗口时留一秒

切到终端后停一秒再说话。这样老师能看清当前窗口，观众也不会觉得画面跳得太快。

### 5.5 语速慢一点

建议每分钟 220 到 260 个汉字，遇到关键条件时更慢。不要为了赶时间把全部代码念完。

| 3:10 到 4:10 | 运行 `errors.pl0`，讲六个错误码 |
| 4:10 到 4:40 | 总结 |

精简版只保留这些关键条件：

```text
currentSymbol != Symbol.PERIOD
currentColumn >= currentLine.length()
line == null
tokenReady || !inputFinished
identifierTooLong
numberText.length() > MAX_NUMBER_LENGTH
symbol == null
```

其他 `if` 在精简视频中不需要逐条展开，可以在总结里说具体分类条件已在文档和源码注释中说明。
