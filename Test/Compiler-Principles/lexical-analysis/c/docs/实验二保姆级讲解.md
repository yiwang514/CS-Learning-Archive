## 1. 实验二到底在做什么

可以把词法分析器理解成“给源程序拆单词并贴标签的机器”。

例如这一行：

```text
const m = 7;
```

词法分析器会把这一行拆成下面这些单词：

```text
const   -> 关键字
m       -> 标识符
=       -> 特殊符号
7       -> 整常数
;       -> 特殊符号
```

PL/0 的编译器不能直接看懂一整段文字。它必须先被词法分析器拆成一个一个的 Token，后面的语法分析器才能处理这些 Token。

所以本实验的程序只做“拆词和分类”，不负责计算 `7 + 8`，也不负责检查程序写得有没有语法错误。

“词法分析器的作用，是把 PL/0 源程序拆成 Token。Token 就是编译器能认识的单词。每个 Token 我会记录四类信息：类别、单词内容、行号、列号。”

### 解释保留字和标识符怎么区分

“程序里放了一张保留字表。扫描到一个由字母开头的单词时，我不会只看第一个字母，而是先把整个连续单词读出来，再和保留字表比较。如果在表里就是关键字，不在表里就是用户自己定义的标识符。这样就能区分 `begin` 和 `beginner`，也能区分 `if` 和 `ifx`。”

## 5. 第一轮：从整体理解代码

下面按代码从上到下的顺序解释，用于先建立整体感觉。如果你觉得这里讲得不够细，直接看第 6 节，那里按 A、B、C 三个等级把 `lexical-analysis/c/src/pl0lex.c` 里的每一个函数都补全了。

### 5.1 常量和 Token 类别

```c
#define MAX_ID_LEN 10
#define MAX_DIGITS 14
```

PL/0 规定：

- 标识符最长 10 个字符
- 整数最多 14 位

```c
typedef enum {
    TOK_IDENTIFIER,
    TOK_INTEGER,
    TOK_KEYWORD,
    TOK_SPECIAL,
    TOK_ERROR,
    TOK_EOF
} TokenKind;
```

这是 Token 的“类别”。可以理解成给单词贴的标签：

```text
IDENTIFIER  标识符，例如 m、x、y
INTEGER     整常数，例如 7、85
KEYWORD     关键字，例如 begin、if
SPECIAL     特殊符号，例如 +、=、:=
ERROR       词法错误
EOF         文件结束
```

### 5.2 Token 结构体

```c
typedef struct {
    TokenKind kind;
    char lexeme[MAX_TEXT];
    char message[MAX_TEXT];
    int line;
    int column;
} Token;
```

解释：

- `kind`：这个 Token 是标识符、数字还是关键字
- `lexeme`：这个 Token 的原始文本
- `message`：如果是错误，错误信息存在这里
- `line` 和 `column`：这个 Token 在源文件里的位置

### 5.3 保留字表

```c
static const char *keywords[] = {
    "begin", "call", "const", "do", "end", "if", "odd",
    "procedure", "read", "then", "var", "while", "write"
};
```

这里就是“关键字名单”。扫描完一个单词后，拿它跟这张表比较。

`read` 和 `write` 也放在里面，是因为很多 PL/0 教学版本用它们做输入输出。如果老师指定的保留字只有 11 个，就把这两个删掉。

### 5.4 判断字符类型

```c
static int is_letter_char(int c)
```

判断一个字符是不是字母。

```c
static int is_digit_char(int c)
```

判断一个字符是不是数字。

```c
static int is_alnum_char(int c)
```

判断一个字符是不是字母或数字。

PL/0 标识符的规则是：第一个字符必须是字母，后面可以跟字母或数字。

### 5.5 跳过空白和注释

```c
static int skip_ignored(void)
```

它会连续跳过：

```text
空格
制表符
回车
换行
/* ... */ 注释
```

只要读到 `/*`，就调用 `skip_comment()`，一直读到 `*/`。

如果整个文件读完都没找到 `*/`，就报告“未闭合注释”。

### 5.6 识别标识符和关键字

```c
static Token scan_word(int token_line, int token_column, size_t start)
```

流程是：

1. 从当前字母开始，不断读后续的字母和数字
2. 得到完整单词
3. 如果长度超过 10，报错
4. 拿完整单词查保留字表
5. 查到就返回 `TOK_KEYWORD`
6. 查不到就返回 `TOK_IDENTIFIER`

这里最关键的一点是：必须先读完整单词，再查表。

例子：

```text
if    读完整后查表 -> 关键字
ifx   读完整后查表 -> 标识符
BEGIN 读完整后查表 -> 关键字
```

### 5.7 识别整数

```c
static Token scan_number(int token_line, int token_column, size_t start)
```

流程是：

1. 从数字开始，不断读数字
2. 如果位数超过 14，报错
3. 如果数字后面紧跟字母，例如 `12abc`，报错
4. 否则返回 `TOK_INTEGER`

`12abc` 不算“一个合法数字加一个合法标识符”，因为它们之间没有分隔符，编译器无法可靠切分。

### 5.8 识别特殊符号

```c
static Token scan_special(int token_line, int token_column, size_t start)
```

它处理这些符号：

```text
+ - * / ( ) = , . ; := < <= <> > >=
```

其中 `:=`、`<=`、`<>`、`>=` 是两个字符组成的特殊符号，所以程序会多看一个字符再决定。

例如看到 `<` 后：

- 下一个是 `=`，就返回 `<=`
- 下一个是 `>`，就返回 `<>`
- 否则返回 `<`

看到单独的 `:` 时报错，因为 PL/0 里只有 `:=` 合法。

### 5.9 核心独立过程

```c
static Token next_token(void)
```

这是整个词法分析器的核心，也是老师要求“实现为一个独立过程”的地方。

它的流程是：

1. 先忽略空格、换行和注释
2. 看当前字符
3. 如果是字母，进入标识符/关键字处理
4. 如果是数字，进入整数处理
5. 如果是符号，进入特殊符号处理
6. 如果文件结束，返回 EOF Token

每调用一次 `next_token()`，就得到一个 Token。

### 5.10 main 函数

```c
int main(int argc, char **argv)
```

它负责：

1. 打开用户提供的 `.pl0` 文件
2. 把整个文件读进内存
3. 反复调用 `next_token()`
4. 打印每个 Token
5. 最后统计 Token 数量和错误数量

发现词法错误时，程序返回退出码 1；没有错误时返回 0。这样脚本可以自动判断运行结果。

### 6.3 A 级：`next_token`

这是老师最可能要求你解释的函数。

```c
static Token next_token(void)
{
    int token_line;
    int token_column;
    size_t start;
    int c;

    if (skip_ignored() < 0) {
        Token eof_token = make_token(TOK_EOF, line, current_column(), pos, pos);
        return eof_token;
    }

    c = current_char();
    if (c == EOF) {
        return make_token(TOK_EOF, line, current_column(), pos, pos);
    }

    token_line = line;
    token_column = current_column();
    start = pos;

    if (is_letter_char(c)) {
        return scan_word(token_line, token_column, start);
    }
    if (is_digit_char(c)) {
        return scan_number(token_line, token_column, start);
    }
    return scan_special(token_line, token_column, start);
}
```

逐行理解：

1. `token_line`、`token_column`、`start` 用来记录这个 Token 从哪里开始。
2. 先调用 `skip_ignored()`，把空格、换行和注释全部扔掉。
3. 如果注释没有正常结束，`skip_ignored()` 返回负数，程序直接返回 EOF Token。
4. `current_char()` 看现在指向哪个字符。
5. 如果已经是文件末尾，返回 EOF Token。
6. 记录起始行、起始列和起始位置。
7. 当前字符是字母，交给 `scan_word()`，负责标识符和关键字。
8. 当前字符是数字，交给 `scan_number()`，负责整数。
9. 都不是，就交给 `scan_special()`，负责 `+`、`=`、`:=` 这类特殊符号。

所以 `next_token()` 本身不负责具体分类，它像总调度员，根据第一个字符决定调用谁。

### 6.4 A 级：`skip_comment` 和 `skip_ignored`

#### `skip_comment`

```c
static int skip_comment(void)
{
    int start_line = line;
    int start_column = current_column();

    advance(); /* '/' */
    advance(); /* '*' */

    while (1) {
        if (pos >= source_len) {
            report_error(start_line, start_column, "unterminated comment");
            return -1;
        }
        if (current_char() == '/' && pos + 1 < source_len &&
            source[pos + 1] == '*') {
            advance();
            advance();
        } else if (current_char() == '*' && pos + 1 < source_len &&
                   source[pos + 1] == '/') {
            advance();
            advance();
            return 0;
        } else {
            advance();
        }
    }
}
```

解释：

1. 进入函数时，已经确认当前字符是 `/`，下一个字符是 `*`。
2. 先保存注释开始的位置，方便报“未闭合注释”时告诉用户在哪一行。
3. `advance()` 两次，把 `/*` 两个字符消费掉。
4. 循环里不断向后看。
5. 如果已经读到文件末尾，说明没有 `*/`，输出“unterminated comment”并返回 `-1`。
6. 如果看见 `*/`，就把这两个字符消费掉并返回 0，表示注释正常结束。
7. 其他字符一律 `advance()`，也就是忽略掉。
8. 代码里还有一个 `/*` 分支，作用是当注释内容里又出现 `/*` 时直接把这两个字符一起消费掉，避免内容里的 `*` 被误当成注释结束符。这份实现按一层注释处理，不做真正的嵌套计数。

#### `skip_ignored`

```c
static int skip_ignored(void)
{
    while (1) {
        int c = current_char();
        while (c == ' ' || c == '\t' || c == '\r' || c == '\n') {
            advance();
            c = current_char();
        }
        if (c == '/' && pos + 1 < source_len && source[pos + 1] == '*') {
            if (skip_comment() < 0) {
                return -1;
            }
            continue;
        }
        return 0;
    }
}
```

解释：

1. 外层 `while (1)` 表示要一直清理，直到遇到真正需要分析的字符。
2. 内层循环把空格、制表符、回车、换行全部跳过。
3. 跳过空白后如果看见 `/*`，就调用 `skip_comment()`。
4. 注释结束后，`continue` 回到外层循环，继续检查后面是否还有空格或注释。
5. 如果当前字符不是空白，也不是注释开头，就返回 0，告诉 `next_token()` 可以开始识别单词了。

### 6.5 A 级：`scan_word` 和 `is_keyword_at`

#### `is_keyword_at`

```c
static int is_keyword_at(size_t start, size_t end)
{
    size_t i;

    for (i = 0; i < sizeof(keywords) / sizeof(keywords[0]); i++) {
        size_t length = strlen(keywords[i]);
        size_t j;

        if (end - start != length) {
            continue;
        }
        for (j = 0; j < length; j++) {
            if (to_lower_ascii(source[start + j]) != keywords[i][j]) {
                break;
            }
        }
        if (j == length) {
            return 1;
        }
    }
    return 0;
}
```

这个函数判断源程序里从 `start` 到 `end` 的这一段是不是保留字。

1. 外层循环遍历保留字表。
2. `strlen(keywords[i])` 得到当前保留字的长度。
3. 如果源程序那段文本长度和保留字长度不一样，直接 `continue`。例如 `ifx` 长度是 3，`if` 长度是 2，所以不会把 `ifx` 误认成 `if`。
4. 内层循环逐个字符比较。
5. 比较时使用 `to_lower_ascii`，所以 `BEGIN` 也能和 `begin` 匹配。
6. 只要有一个字符不同就 `break`。
7. 如果 `j == length`，表示每个字符都相同，返回 1，说明是保留字。

#### `scan_word`

```c
static Token scan_word(int token_line, int token_column, size_t start)
{
    while (is_alnum_char(current_char())) {
        advance();
    }

    if (pos - start > MAX_ID_LEN) {
        return make_error_token(token_line, token_column, start, pos,
                                "identifier is longer than 10 characters");
    }

    if (is_keyword_at(start, pos)) {
        return make_token(TOK_KEYWORD, token_line, token_column, start, pos);
    }

    return make_token(TOK_IDENTIFIER, token_line, token_column, start, pos);
}
```

解释：

1. `start` 是单词开始位置。
2. 只要当前字符是字母或数字，就调用 `advance()` 向后读。
3. 循环结束后，`pos` 停在单词后面的第一个非法字符上。
4. `pos - start` 就是单词长度。
5. 如果超过 10，生成错误 Token。
6. 调用 `is_keyword_at(start, pos)` 查保留字表。
7. 是保留字就生成 `TOK_KEYWORD`。
8. 不是保留字就生成 `TOK_IDENTIFIER`。

这里体现“先读完整单词，再查保留字表”，所以 `beginner` 会被读完整，然后发现不在表里，最终当成标识符。

### 6.6 A 级：`scan_number`

```c
static Token scan_number(int token_line, int token_column, size_t start)
{
    size_t digit_count;
    Token token;

    while (is_digit_char(current_char())) {
        advance();
    }
    digit_count = pos - start;

    if (digit_count > MAX_DIGITS) {
        while (is_alnum_char(current_char())) {
            advance();
        }
        return make_error_token(token_line, token_column, start, pos,
                                "integer constant has more than 14 digits");
    }

    if (is_letter_char(current_char())) {
        while (is_alnum_char(current_char())) {
            advance();
        }
        return make_error_token(token_line, token_column, start, pos,
                                "number cannot be followed by a letter");
    }

    token = make_token(TOK_INTEGER, token_line, token_column, start, pos);
    return token;
}
```

解释：

1. 进入函数时已经确定当前字符是数字。
2. 循环不断读数字，直到遇到非数字。
3. `digit_count = pos - start` 统计共有多少位。
4. 如果超过 14 位，继续把后面的字母数字读完，再返回超长整数错误。继续读完是为了避免残留字符影响下一次扫描。
5. 如果数字后面紧跟着字母，例如 `12abc`，继续读完 `abc`，然后返回“数字后不能跟字母”错误。
6. 以上都没问题，生成 `TOK_INTEGER` Token。

### 6.7 A 级：`scan_special`

```c
static Token scan_special(int token_line, int token_column, size_t start)
{
    int c = current_char();

    advance();

    if (c == '+') {
        return make_token(TOK_SPECIAL, token_line, token_column, start, pos);
    }
    if (c == '-') {
        return make_token(TOK_SPECIAL, token_line, token_column, start, pos);
    }
    if (c == '*') {
        return make_token(TOK_SPECIAL, token_line, token_column, start, pos);
    }
    if (c == '/') {
        return make_token(TOK_SPECIAL, token_line, token_column, start, pos);
    }
    if (c == '(' || c == ')' || c == '=' || c == ',' ||
        c == '.' || c == ';') {
        return make_token(TOK_SPECIAL, token_line, token_column, start, pos);
    }
    if (c == ':') {
        if (current_char() == '=') {
            advance();
            return make_token(TOK_SPECIAL, token_line, token_column, start, pos);
        }
        return make_error_token(token_line, token_column, start, pos,
                                "':' must be followed by '='");
    }
    if (c == '<') {
        if (current_char() == '=' || current_char() == '>') {
            advance();
        }
        return make_token(TOK_SPECIAL, token_line, token_column, start, pos);
    }
    if (c == '>') {
        if (current_char() == '=') {
            advance();
        }
        return make_token(TOK_SPECIAL, token_line, token_column, start, pos);
    }

    if (c >= 32 && c < 127) {
        char message[MAX_TEXT];
        snprintf(message, sizeof(message), "illegal character '%c'", c);
        return make_error_token(token_line, token_column, start, pos, message);
    }
    {
        char message[MAX_TEXT];
        snprintf(message, sizeof(message), "illegal character with code %d", c);
        return make_error_token(token_line, token_column, start, pos, message);
    }
}
```

解释：

1. `c` 保存当前字符。
2. `advance()` 先把当前字符消费掉，此时 `pos` 已经在下一个字符上。
3. `+`、`-`、`*`、`/` 单独成 Token。
4. `(`、`)`、`=`、`,`、`.`、`;` 单独成 Token。
5. 看到 `:` 时，要看下一个字符是不是 `=`。是 `=` 就组成 `:=`；不是就报错。因为 PL/0 里不允许单独的 `:`。
6. 看到 `<` 时，看下一个是 `=` 还是 `>`，分别组成 `<=` 和 `<>`；都不是就只返回 `<`。
7. 看到 `>` 时，看下一个是不是 `=`，是就返回 `>=`。
8. 一个符号都没有匹配时，说明这个字符非法。能打印的普通字符显示成 `illegal character '@'` 这种形式；不能打印的字符显示字符编码。

这些函数代码很简单，主要作用是让上面的 A 级和 B 级函数更好写。

## 7. 老师可能问你的问题

### 问：源文件是哪一个？

答：实验二的源码是 `lexical-analysis/c/src/pl0lex.c`。原来的 `pl0-compiler/c/src/pl0.c` 是实验一或教学编译器文件，实验二没有改动它。

### 问：怎么区分标识符和保留字？

答：先把整个连续单词读出来，再查保留字表。表中存在就是关键字，不存在就是标识符。

### 问：为什么 `BEGIN` 也能识别成关键字？

答：程序查表时忽略大小写，所以 `BEGIN`、`Begin`、`begin` 都会被识别为关键字，但输出保留原始写法。

### 问：`12abc` 为什么报错？

答：因为数字后面紧跟字母时无法确定它是一个整数还是标识符，PL/0 词法规则不允许这种写法。

### 问：注释为什么没有输出？

答：`next_token()` 在正式识别单词前先调用 `skip_ignored()`，遇到 `/*` 后一直跳过，直到 `*/`，所以注释不会生成 Token。

### 问：Token 表里的 EOF 是什么？

答：EOF 表示文件已经读完了，不是源程序里的一个单词。

### 问：遇到错误为什么不直接退出？

答：程序把错误当成一种 Token 记录并继续扫描，最后统一统计。这样一次运行能发现多个错误。

## 8. 如果录制时紧张，可以只讲这几句

1. 源文件是 `lexical-analysis/c/src/pl0lex.c`
2. 词法分析器的作用是把源程序拆成 Token
3. 核心函数是 `next_token()`
4. 标识符先完整读出，再和保留字表比较
5. 空格、换行、注释都被忽略
6. 非法字符、超长标识符、超长整数、未闭合注释都能报错
