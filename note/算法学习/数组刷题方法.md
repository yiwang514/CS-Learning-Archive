# 数组刷题方法

# 1. 双指针法 (Two Pointers)

这是数组题中最常用的技巧。通常分为两种形式：

- **左右指针（对撞指针）：**两个指针分别位于数组的**左端（0）和右端（length - 1）**，根据某种条件向中间靠拢。

  - **适用场景：** 有序数组找两数之和、翻转数组、判断回文。

  - **例子：** 二分查找（Binary Search）其实就是一种特殊的左右指针。

    核心逻辑模板

    ```java
    public void solve(int[] nums) {
        int left = 0;
        int right = nums.length - 1;
        
        while (left < right) {
            // 1. 计算当前的逻辑（比如求和）
            int sum = nums[left] + nums[right];
            
            // 2. 根据条件移动指针
            if (sum == target) {
                return new int[]{left, right};
            } else if (sum < target) {
                left++; // 总和太小，左指针右移（数值增大）
            } else {
                right--; // 总和太大，右指针左移（数值减小）
            }
        }
    }
    ```

- **快慢指针：** 两个指针同向移动，**移动的频率或触发移动的条件**不同。快指针（fast）负责探路，慢指针（slow）负责记录符合条件的“边界”。

  - **适用场景：** 原地删除重复元素、链表找环（虽然是链表，但逻辑一致）、滑动窗口的基础。、

    ### 实战案例：删除有序数组中的重复项

    假设数组是 `[1, 1, 2]`，我们需要原地修改，让它变成 `[1, 2, ...]`。

    ```java
    public int removeDuplicates(int[] nums) {
     
        if (nums.length == 0) return 0;
        
        int slow = 0; // 记录不重复元素的存放位置
        for (int fast = 1; fast < nums.length; fast++) {
            // 如果快指针发现了新元素（跟慢指针指向的不同）
            if (nums[fast] != nums[slow]) {
                slow++;           // 慢指针往前挪一步
                nums[slow] = nums[fast]; // 把新元素存进来
            }
        }
        return slow + 1; // 返回新长度
    }
    ```

------



## 为什么双指针在 Java 刷题中这么香？

### 1. 空间效率极高

在 Java 里，数组的内存是连续的。双指针通常只额外定义了两个 `int` 变量（索引），所以空间复杂度是 **$O(1)$**。这在面试中是非常加分的。

### 2. 避免冗余计算

以“两数之和”为例，普通暴力解法是：

- 固定第一个数，遍历剩下的。
- 固定第二个数，再遍历剩下的。
- 这做了很多无意义的重复比较。而对撞指针利用了**有序性**，一次移动就能排除掉一整堆不可能的组合。

### 3. Java 的特有小细节

- **越界检查：** 写 `while (left < right)` 而不是 `while (left <= right)` 要根据具体题目决定（比如二分查找就需要 `<=`）。
- **交换逻辑：** Java 没有内置的 `swap(nums[i], nums[j])` 这种函数，刷数组题时建议随手写一个私有的 `swap` 方法，代码会整洁很多。

```
private void swap(int[] nums, int i, int j) {
    int temp = nums[i];
    nums[i] = nums[j];
    nums[j] = temp;
}
```

------

## 避坑指南

1. **忘记对数组排序：** 绝大多数对撞指针题目，前提都是数组**有序**。如果题目给的是无序数组，记得先调 `Arrays.sort()`。
2. **死循环：** 如果你在循环体里忘记写 `left++` 或 `right--`，或者移动的条件判断错了，程序就会“卡死”。写完代码后，肉眼模拟一下指针移动是很重要的。

------

##  **双指针法的底层原理**

为什么双指针能把 O(n^2) 变成 O(n)？

### 1. 缩减搜索范围 (Reducing Search Space)

在暴力解法中，我们通常用两层 `for` 循环遍历所有可能的组合（如所有的数对）。

- **原理：** 双指针通过逻辑判断，**一次性排除掉一批不可能的选项**。
- **例子：** 在有序数组中找两数之和。如果 `nums[left] + nums[right] < target`，因为数组是有序的，`left` 和比 `right` 更小的数相加只会更小。所以，我们直接排除掉 `left` 与中间所有数的组合，放心地让 `left++`。

### 2. 利用单调性 (Monotonicity)

这是双指针能生效的前提。

- **原理：** 当一个指针向右移动时，它产生的结果（如和、长度）是**单调增加或减少**的。这种确定性让我们不需要回过头去检查已经跳过的元素。

### 3. 快慢步数差 (Distance Gap)

- **原理：** 两个指针以不同的速度移动，当“快指针”到达终点时，两个指针之间的**相对距离**或**位置关系**正好构成了问题的答案。

------

## 二、 双指针法能解决的题型

基于上述原理，当你遇到以下几类需求时，基本可以确定要用双指针：

### 1. 搜索与匹配类（对撞指针）

这类题目利用**数组有序**的特性，从两端向中间收缩搜索空间。

- **有序数组求和：** 给定目标值，找两个或三个数（如：两数之和 II、三数之和）。
- **元素交换/翻转：** 需要对称处理数组元素（如：反转字符串、验证回文串）。
- **盛水最多的容器：** 这种题虽然数组无序，但左右边界的移动逻辑具有单调性（缩减搜索空间）。

### 2. 原地修改类（快慢指针）

这类题目要求**空间复杂度为 O(1)**，且通常是在原始数组上进行“过滤”或“移动”。

- **去重/剔除元素：** 在有序数组中删除重复项，或删除特定数值（如：移除元素）。
- **分类与排序：** 按照某种属性将数组分成两部分（如：移动零到末尾、奇偶排序）。

### 3. 链表结构类（快慢指针）

但数组的索引操作与链表的指针操作原理一致。

- **中点定位：** 快指针走两步，慢指针走一步，快指针到头时，慢指针在中点。
- **环路检测：** 著名的“龟兔赛跑”算法（判断链表是否有环）。
- **倒数第 K 个：** 让快指针先走 K 步，然后两个指针同步走。

### 4. 区间/子数组类（滑动窗口）

这属于快慢指针的变体，通常处理**“连续”**的子区间。

- **定长/变长区间求值：** 寻找满足条件的最小长度子数组或最大总和（如：长度最小的子数组）。

------

## 三、 Java 实现的小贴士

在刷题时，Java 的一些特性会直接影响双指针的实现：

- **数组长度固定：** `nums.length` 是属性，不是方法。
- **防止溢出：** 计算中点时，习惯写 `int mid = left + (right - left) / 2;` 而不是 `(left + right) / 2`。
- **对象比较：** 如果数组里装的是 `Integer` 对象而非 `int`，记得用 `.equals()` 比较，而不是 `==`。

# 2. 滑动窗口 (Sliding Window)

滑动窗口其实是双指针的一种演变，主要用于处理**“连续子数组”**的问题。

## 一、 滑动窗口的底层原理

### 1. 增量更新 (Incremental Update)

这是滑动窗口最核心的哲学。

- **暴力解法：** 每次计算子数组（区间）时，都重新从头开始累加。比如计算长度为 3 的子数组和，算完 `[0,1,2]`，再从头算 `[1,2,3]`。
- **窗口原理：** 当窗口向右移动一格时，**中间的大部分元素其实是没有变化的**。我们只需要“加上进入窗口的新元素，减去离开窗口的旧元素”。
- **结果：** 将时间复杂度从 **O(n * k)** 降低到 **O(n)**。

### 2. 空间局部性与单调性

- 滑动窗口利用了数组元素在内存中连续分布的特性。
- 它通常要求某种**单调性**：比如数组元素全为正数，那么窗口越长，总和一定越大。这种确定性让我们敢于在满足条件时收缩左边界，而不担心错过最优解。

------

## 二、 滑动窗口能解决的题型

只要题目出现 **“子数组” (Subarray)** 或 **“子串” (Substring)**，且要求是 **“连续”** 的，你的第一反应就应该是滑动窗口。

### **1. 固定窗口大小**

题目给定了窗口的长度 K，求某个特征值。

- **典型题：** 子数组最大平均数、包含特定字符数量的定长子串。
- **技巧：** 先初始化第一个窗口，然后开始循环，每次 `sum += nums[right] - nums[left]`。

### **2. 变长窗口（寻找最短/最小）**

窗口大小不固定，目标是找到满足条件的**最短**区间。

- **典型题：** 长度最小的子数组（和大于等于 S）。
- **原理：** `right` 主动向右移，直到满足条件；然后 `left` 被动向右移，试图“榨干”水分，寻找极限最短长度。

### 3. 变长窗口（寻找最长）

窗口大小不固定，目标是找到满足条件的**最长**区间。

- **典型题：** 无重复字符的最长子串、最多替换 K 个元素后的最长连续 1。
- **原理：** `right` 不断向右扩充，一旦**违背**了题目条件（比如出现了重复字符），`left` 就开始收缩，直到重新满足条件为止。

------

## 三、 Java 实现模板（变长窗口）

这是最通用的模板，建议理解并背下来，大部分题只是在修改里面的 `condition`。

```
public int slidingWindow(int[] nums) {
    int left = 0, right = 0;
    int res = 0; // 或者 Integer.MAX_VALUE
    // 1. 维护窗口内的状态（如 sum, count, HashMap 等）
    int windowState = 0; 

    while (right < nums.length) {
        // 2. 【入窗】：把右边的元素加入窗口，更新状态
        windowState += nums[right];
        
        // 3. 【收缩】：判断是否需要移动左边界
        // 寻找最短时用 while，寻找最长时用 if（视题目而定）
        while (windowState >= target) { 
            // 4. 【更新答案】：在这里记录满足条件的解
            res = Math.min(res, right - left + 1);
            
            // 5. 【出窗】：把左边的元素移出窗口，更新状态
            windowState -= nums[left];
            left++;
        }
        right++;
    }
    return res;
}
```

------

## 四、 为什么滑动窗口在 Java 中很高效？

1. **对象复用：** 在处理字符串子串（Substring）时，如果你不停地调用 `s.substring(i, j)`，Java 会频繁创建新的字符串对象。而滑动窗口只操作索引（指针），**零对象创建**。
2. **容器配合：** Java 的 `HashMap` 或数组（作为频率表）在滑动窗口中非常强大。
   - 如果是处理 ASCII 字符，直接定义 `int[] map = new int[128];` 代替 `HashMap`，性能会起飞。
3. **防止冗余操作：** 像 `HashSet.contains()` 这种操作在窗口滑动过程中只需要增量进行，不需要每步重新扫描。

------

## 避坑指南

- **边界计算：** 窗口的长度是 `right - left + 1`，这个 `+1` 经常容易忘。
- **初始值设置：** 找最小长度时，初始值设为 `Integer.MAX_VALUE`；找最大长度时，设为 `0`。
- **收缩条件：** 想清楚是“满足条件时收缩”还是“违背条件时收缩”。

**对比一下：**

- **双指针（对撞）：** 是从两头往中间挤，主要是为了**排除**不可能的选项。
- **滑动窗口：** 是从左往右拉，主要是为了**捕获**一段连续的范围。

# 3. 前缀和 (Prefix Sum)

当你发现题目反复要求某个**区间范围内的和**时，就要想到前缀和。

## 一、 前缀和的底层原理

### 1. 预处理与复用 (Pre-computation)

前缀和的核心在于：**通过一次 O(n) 的遍历，将数组中每个位置之前的“累积信息”保存下来。**

- **原理：** 定义一个数组 `P`，其中 `P[i]` 表示原数组从下标 `0` 到 `i-1` 的所有元素之和。
- **数学表达：** P[i] = nums[0] + nums[1] + ... + nums[i-1]。

### 2. 差分逆运算

这是前缀和最精妙的地方。

- **原理：** 既然 P[j] 是前 j 个数的和，P[i] 是前 i 个数的和，那么要求区间 [i, j-1] 的和，只需要做一次减法：Sum(i, j-1) = P[j] - P[i]。
- **效果：** 它把原本需要 O(n) 遍历才能得到的区间和，瞬间降到了 **O(1)**。这在处理高频次区间查询时具有压倒性优势。

------

## 二、 前缀和能解决的题型

当你看到题目要求**“频繁计算子数组和”**或者**“寻找特定和的子数组”**时，前缀和就是首选。

### 1. 静态区间和查询

题目会给出很多个询问，每个询问要求输出数组中 [L, R] 范围内的数字总和。

- **例子：** 区域和检索 - 数组不可变（LeetCode 303）。
- **原理：** 直接查表计算，查询效率极高。

### 2. 子数组之和等于 K

寻找数组中总和等于 K 的连续子数组个数或索引。

- **例子：** 和为 K 的子数组（LeetCode 560）。
- **原理：** 结合 **HashMap**。在遍历过程中记录前缀和出现的次数。如果当前前缀和为 `currSum`，我们只需要看 `currSum - K` 在之前是否出现过。

### 3. 二维矩阵区域求和

在一个矩阵中，快速计算任意子矩形的数值总和。

- **原理：** 一维前缀和的升级版。通过“容斥原理”（加加大矩形，减去上、左矩形，加上重叠的左上矩形）实现 O(1) 查询。

### 4. 统计类问题（转化思路）

有时候数组里不是数字，而是“状态”。

- **例子：** 统计数组中奇数和偶数个数相等的子数组。
- **技巧：** 把奇数看作 1，偶数看作 -1。问题就变成了寻找“和为 0 的子数组”，瞬间转化成前缀和问题。

------

## 三、 Java 实现模板

在 Java 中实现前缀和，最关键的习惯是**“长度多开一位”**。

```java
public class PrefixSum {
    private int[] preSum;

    public PrefixSum(int[] nums) {
        int n = nums.length;
        // 1. 多开一位，preSum[0] 默认为 0，方便处理边界
        preSum = new int[n + 1];
        for (int i = 0; i < n; i++) {
            // 2. 递推公式：当前前缀和 = 前一个前缀和 + 当前元素
            preSum[i + 1] = preSum[i] + nums[i];
        }
    }

    // 3. 计算区间 [left, right] 的和（包含左右边界）
    public int query(int left, int right) {
        // 公式：P[right + 1] - P[left]
        return preSum[right + 1] - preSum[left];
    }
}
```

------

## 四、 为什么前缀和在 Java 中很实用？

1. **内存连续性：** `preSum` 数组在内存中是连续的，Java 的 CPU 缓存机制对这种线性访问非常友好，读取速度极快。
2. **避免整型溢出：** 在 Java 中，如果数组元素很大，前缀和很容易超过 `int` 的范围（21亿）。
   - **技巧：** 刷题时养成习惯，如果题目提示数值较大，直接用 `long[] preSum` 存储。
3. **配合 Map 容器：** `HashMap<Integer, Integer>` 是前缀和的最佳拍档。
   - 比如 `map.put(0, 1)`：这个操作能解决“子数组从下标 0 开始”的边界问题，是很多初学者容易漏掉的细节。

------

## 避坑指南

- **索引错位：** 这是前缀和最容易出错的地方。记住：`preSum[i]` 通常表示前 `i` 个元素的和（即 `nums[0...i-1]`）。
- **数据更新：** 前缀和适用于**静态数组**。如果数组元素会频繁修改，前缀和数组就需要重新维护（O(n)），这时候就需要更高级的数据结构，比如**树状数组（BIT）\**或\**线段树**了。

# 4. 排序 (Sorting)

很多数组题在无序状态下很难做，但一**排序**就豁然开朗。

- **思路：** 拿到题先问自己：如果数组是有序的，是不是就好办了？
- **适用场景：** 寻找重复元素、找出最接近的数、区间合并。
- **Java 工具：** `Arrays.sort(nums);` （内部使用的是优化的快速排序或归并排序）。

# 5. 空间换时间 (Hash Table)

它的核心思想非常朴素：**与其每次都费劲去寻找或计算，不如把结果先存起来，下次直接拿。**

而在 Java 中，哈希表（Hash Table，即 `HashMap` 或 `HashSet`）就是实现这一思想的终极武器。

------

## 一、 哈希表的底层原理

### 1. 瞬间定位 (Constant Time Lookup)

- **暴力解法：** 在一个数组里找一个数，你需要从头扫到尾（$O(n)$）。
- **哈希原理：** 它通过哈希函数将“键（Key）”映射为一个数字（索引）。这就好比给每个数据分了一个固定的“房间号”，你找它时不需要挨个敲门，而是直接去那个房间。
- **效果：** 查找、插入和删除的时间复杂度在理想情况下都是 **$O(1)$**。

### 2. 记忆化存储 (Memoization)

- **原理：** 记录已经遍历过的元素及其相关信息（下标、出现次数等）。当你走到数组后面时，可以瞬间“回想起”前面的情况，从而判断当前元素与之前的元素是否能凑成答案。

------

## 二、 哈希表法能解决的题型

当你发现题目涉及**“查找”、“去重”、“统计”**或者**“寻找匹配对”**时，哈希表就是你的第一选择。

### 1. 匹配对寻找（两数之和类）

- **场景：** 寻找数组中是否存在两个数，它们的和等于目标值。
- **原理：** 遍历到 `x` 时，去哈希表里查一下 `target - x` 是否在之前出现过。
- **优势：** 把双层循环（$O(n^2)$）直接降维到单层循环（$O(n)$）。

### 2. 频率统计与去重

- **场景：** 统计每个数字出现的次数，或者找出数组中第一个只出现一次的字符。
- **原理：** 以元素为 Key，频率为 Value 进行计数。
- **例子：** 存在重复元素（LeetCode 217）、前 K 个高频元素。

### 3. 关联关系存储（分组）

- **场景：** 将具有某种共同特征的元素聚在一起。
- **例子：** 字母异位词分组（LeetCode 49）。把排序后的字符串作为 Key，原始字符串列表作为 Value。

### 4. 缺失/重复数字（数值范围有限时）

- **场景：** 数组长度为 $n$，数值范围也在 $[0, n]$ 之间。
- **原理：** 这类题虽然可以用 `HashSet`，但更高级的做法是**“把原数组当成哈希表”**（即原地哈希），利用下标来存储信息，从而达到 $O(1)$ 的空间复杂度。

------

## 三、 Java 实现模板与技巧

Java 程序员在用哈希表刷题时，有几个非常“爽”的 API 必须掌握：

### 1. 经典频率统计

Java

```Java
Map<Integer, Integer> map = new HashMap<>();
for (int num : nums) {
    // 技巧：一行代码搞定计数，不用写 if-else
    map.put(num, map.getOrDefault(num, 0) + 1);
}
```

### 2. 数组替代哈希表（性能杀手锏）

如果题目明确告诉你是小写字母或者数值范围很小，**永远优先使用数组**。

```Java
// 统计 26 个字母出现的次数
int[] count = new int[26];
for (char c : s.toCharArray()) {
    count[c - 'a']++; 
}
// 数组的查找也是 O(1)，但比 HashMap 快得多，且省内存
```

### 3. 两数之和模板

```Java
public int[] twoSum(int[] nums, int target) {
    Map<Integer, Integer> map = new HashMap<>();
    for (int i = 0; i < nums.length; i++) {
        int complement = target - nums[i];
        if (map.containsKey(complement)) {
            return new int[] { map.get(complement), i };
        }
        map.put(nums[i], i); // 存入：数值 -> 下标
    }
    return new int[0];
}
```

## 四、 为什么在 Java 中要慎用 HashMap？

虽然哈希表很快，但它不是免费的午餐：



1. **空间开销：** `HashMap` 存储的是对象（Integer），相比于基本类型（int），它非常吃内存。

   

   

2. **常数项时间：** 哈希函数的计算和处理哈希冲突是有代价的。在数据量很小时，数组扫描可能比 `HashMap` 还快。

3. **无序性：** 标准 `HashMap` 是无序的。如果你需要保持插入顺序，得用 `LinkedHashMap`；需要按大小排序，得用 `TreeMap`。

------

## 避坑指南

- **修改 Key：** 存入 Map 后，千万不要修改作为 Key 的对象的内容，否则哈希值变了，你就再也找不回这个数据了（虽然数组题里一般 Key 是不可变的 `Integer` 或 `String`，但也得留心）。
- **内存溢出：** 如果数据量达到千万级，无节制地开 `HashMap` 可能会导致 Java 虚拟机（JVM）报 `OutOfMemoryError`。

------

## 一、 HashMap 的底层原理

### 1. 核心本质：散列函数（Hashing）

- **原理：** `HashMap` 内部像是一个巨大的“储物柜数组”。当你存入一个 `Key` 时，Java 会调用这个对象的 `hashCode()` 方法算出一个数字，然后通过取余运算把它转换成数组的下标。
- **效果：** 只要知道 `Key` 是什么，就能瞬间算出它在哪个柜子里，不需要从头到尾翻找。

### 2. 空间换时间（Trade-off）

- **原理：** 为了保证查找速度快，`HashMap` 会预留比实际数据更多的空间。如果柜子快装满了，它会自动“扩容”。
- **代价：** 它比普通的 `int[]` 消耗更多的内存（因为要存储 Entry 对象、处理哈希冲突等）。

------

## 二、 哈希表能解决的题型（原理应用）

基于这种“瞬间定位”的能力，它最擅长以下三类题：

1. **“记账”类（频率统计）：** 统计数组中每个数字出现了几次。利用 `Key` 存数字，`Value` 存次数。
2. **“点名”类（存在性检查）：** 快速判断某个数之前是否出现过。
3. **“配对”类（索引映射）：** 比如两数之和（Two Sum）。遍历到 $B$ 时，瞬间查出 $target - B$ 也就是 $A$ 的下标在哪里。

------

## 三、 必须掌握的核心 API 招式

在刷题时，你不需要背下所有方法，掌握这几个“黄金 API”就够了：

### 1. 基础增删改查

- `put(K key, V value)`：存入一个键值对。如果 `Key` 已存在，会**覆盖**旧值。
- `get(Object key)`：取出 `Value`。如果 `Key` 不存在，返回 `null`。
- `containsKey(Object key)`：**最常用！** 返回 `boolean`，判断这个键在不在。
- `remove(Object key)`：删掉某个键值对。

### 2. 进阶必备（刷题神技）

刷数组题时，这两个方法能让你的代码简洁好几倍：

- **`getOrDefault(Object key, V defaultValue)`**
  - **用途：** 统计次数。如果找不到这个 key，就返回你指定的默认值（通常是 0）。
  - **写法：** `map.put(num, map.getOrDefault(num, 0) + 1);`（这一行代码顶替了以前的 4 行 `if-else`）。
- **`putIfAbsent(K key, V value)`**
  - **用途：** 只有当 `Key` 不存在时才存入。常用于记录某个元素**第一次**出现的下标。

### 3. 遍历方法

当你需要遍历统计结果时：

- `keySet()`：只拿所有的 `Key`。
- `entrySet()`：同时拿 `Key` 和 `Value`（性能最高）。

Java

```Java
for (Map.Entry<Integer, Integer> entry : map.entrySet()) {
    System.out.println("数字: " + entry.getKey() + " 出现了 " + entry.getValue() + " 次");
}
```

------

## 四、 Java 刷题中的“潜规则”

### 1. 泛型只能用包装类

Java 的 `HashMap` 里面不能存基本类型 `int`，必须写成 `HashMap<Integer, Integer>`。

> **冷知识：** 虽然 Java 有“自动装箱”，但在海量数据下，`Integer` 对象会比 `int` 慢很多。如果遇到对性能极其苛刻的题目，有些大佬会用三方库或者自己用数组模拟哈希。

### 2. 初始化大小

如果你已经知道数组长度是 `n`，初始化时可以给个初始容量，减少扩容开销：

```java
Map<Integer, Integer> map = new HashMap<>(n);
```

- `Arrays.fill(nums, 0)`：快速填充初值。
