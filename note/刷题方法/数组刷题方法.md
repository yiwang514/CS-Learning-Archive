# 数组刷题方法

# 1. 双指针法 (Two Pointers)

这是数组题中最常用的技巧。通常分为两种形式：

- **左右指针（对撞指针）：**两个指针分别位于数组的**左端（0）和右端（length - 1）**，根据某种条件向中间靠拢。

  - **适用场景：** 有序数组找两数之和、翻转数组、判断回文。

  - **例子：** 二分查找（Binary Search）其实就是一种特殊的左右指针。

    核心逻辑模板

    ```java
    public void solve(int[] nums) {
        int left = 0;
        int right = nums.length - 1;
        
        while (left < right) {
            // 1. 计算当前的逻辑（比如求和）
            int sum = nums[left] + nums[right];
            
            // 2. 根据条件移动指针
            if (sum == target) {
                return new int[]{left, right};
            } else if (sum < target) {
                left++; // 总和太小，左指针右移（数值增大）
            } else {
                right--; // 总和太大，右指针左移（数值减小）
            }
        }
    }
    ```

- **快慢指针：** 两个指针同向移动，**移动的频率或触发移动的条件**不同。快指针（fast）负责探路，慢指针（slow）负责记录符合条件的“边界”。

  - **适用场景：** 原地删除重复元素、链表找环（虽然是链表，但逻辑一致）、滑动窗口的基础。、

    ### 实战案例：删除有序数组中的重复项

    假设数组是 `[1, 1, 2]`，我们需要原地修改，让它变成 `[1, 2, ...]`。

    ```java
    public int removeDuplicates(int[] nums) {
     
        if (nums.length == 0) return 0;
        
        int slow = 0; // 记录不重复元素的存放位置
        for (int fast = 1; fast < nums.length; fast++) {
            // 如果快指针发现了新元素（跟慢指针指向的不同）
            if (nums[fast] != nums[slow]) {
                slow++;           // 慢指针往前挪一步
                nums[slow] = nums[fast]; // 把新元素存进来
            }
        }
        return slow + 1; // 返回新长度
    }
    ```

------



## 为什么双指针在 Java 刷题中这么香？

### 1. 空间效率极高

在 Java 里，数组的内存是连续的。双指针通常只额外定义了两个 `int` 变量（索引），所以空间复杂度是 **$O(1)$**。这在面试中是非常加分的。

### 2. 避免冗余计算

以“两数之和”为例，普通暴力解法是：

- 固定第一个数，遍历剩下的。
- 固定第二个数，再遍历剩下的。
- 这做了很多无意义的重复比较。而对撞指针利用了**有序性**，一次移动就能排除掉一整堆不可能的组合。

### 3. Java 的特有小细节

- **越界检查：** 写 `while (left < right)` 而不是 `while (left <= right)` 要根据具体题目决定（比如二分查找就需要 `<=`）。
- **交换逻辑：** Java 没有内置的 `swap(nums[i], nums[j])` 这种函数，刷数组题时建议随手写一个私有的 `swap` 方法，代码会整洁很多。

```
private void swap(int[] nums, int i, int j) {
    int temp = nums[i];
    nums[i] = nums[j];
    nums[j] = temp;
}
```

------

## 避坑指南

1. **忘记对数组排序：** 绝大多数对撞指针题目，前提都是数组**有序**。如果题目给的是无序数组，记得先调 `Arrays.sort()`。
2. **死循环：** 如果你在循环体里忘记写 `left++` 或 `right--`，或者移动的条件判断错了，程序就会“卡死”。写完代码后，肉眼模拟一下指针移动是很重要的。

##  **双指针法的底层原理**

为什么双指针能把 O(n^2) 变成 O(n)？

### 1. 缩减搜索范围 (Reducing Search Space)

在暴力解法中，我们通常用两层 `for` 循环遍历所有可能的组合（如所有的数对）。

- **原理：** 双指针通过逻辑判断，**一次性排除掉一批不可能的选项**。
- **例子：** 在有序数组中找两数之和。如果 `nums[left] + nums[right] < target`，因为数组是有序的，`left` 和比 `right` 更小的数相加只会更小。所以，我们直接排除掉 `left` 与中间所有数的组合，放心地让 `left++`。

### 2. 利用单调性 (Monotonicity)

这是双指针能生效的前提。

- **原理：** 当一个指针向右移动时，它产生的结果（如和、长度）是**单调增加或减少**的。这种确定性让我们不需要回过头去检查已经跳过的元素。

### 3. 快慢步数差 (Distance Gap)

- **原理：** 两个指针以不同的速度移动，当“快指针”到达终点时，两个指针之间的**相对距离**或**位置关系**正好构成了问题的答案。

------

## 二、 双指针法能解决的题型

基于上述原理，当你遇到以下几类需求时，基本可以确定要用双指针：

### 1. 搜索与匹配类（对撞指针）

这类题目利用**数组有序**的特性，从两端向中间收缩搜索空间。

- **有序数组求和：** 给定目标值，找两个或三个数（如：两数之和 II、三数之和）。
- **元素交换/翻转：** 需要对称处理数组元素（如：反转字符串、验证回文串）。
- **盛水最多的容器：** 这种题虽然数组无序，但左右边界的移动逻辑具有单调性（缩减搜索空间）。

### 2. 原地修改类（快慢指针）

这类题目要求**空间复杂度为 O(1)**，且通常是在原始数组上进行“过滤”或“移动”。

- **去重/剔除元素：** 在有序数组中删除重复项，或删除特定数值（如：移除元素）。
- **分类与排序：** 按照某种属性将数组分成两部分（如：移动零到末尾、奇偶排序）。

### 3. 链表结构类（快慢指针）

但数组的索引操作与链表的指针操作原理一致。

- **中点定位：** 快指针走两步，慢指针走一步，快指针到头时，慢指针在中点。
- **环路检测：** 著名的“龟兔赛跑”算法（判断链表是否有环）。
- **倒数第 K 个：** 让快指针先走 K 步，然后两个指针同步走。

### 4. 区间/子数组类（滑动窗口）

这属于快慢指针的变体，通常处理**“连续”**的子区间。

- **定长/变长区间求值：** 寻找满足条件的最小长度子数组或最大总和（如：长度最小的子数组）。

------

## 三、 Java 实现的小贴士

在刷题时，Java 的一些特性会直接影响双指针的实现：

- **数组长度固定：** `nums.length` 是属性，不是方法。
- **防止溢出：** 计算中点时，习惯写 `int mid = left + (right - left) / 2;` 而不是 `(left + right) / 2`。
- **对象比较：** 如果数组里装的是 `Integer` 对象而非 `int`，记得用 `.equals()` 比较，而不是 `==`。

# 2. 滑动窗口 (Sliding Window)

滑动窗口其实是双指针的一种演变，主要用于处理**“连续子数组”**的问题。

## 一、 滑动窗口的底层原理

### 1. 增量更新 (Incremental Update)

这是滑动窗口最核心的哲学。

- **暴力解法：** 每次计算子数组（区间）时，都重新从头开始累加。比如计算长度为 3 的子数组和，算完 `[0,1,2]`，再从头算 `[1,2,3]`。
- **窗口原理：** 当窗口向右移动一格时，**中间的大部分元素其实是没有变化的**。我们只需要“加上进入窗口的新元素，减去离开窗口的旧元素”。
- **结果：** 将时间复杂度从 **O(n * k)** 降低到 **O(n)**。

### 2. 空间局部性与单调性

- 滑动窗口利用了数组元素在内存中连续分布的特性。
- 它通常要求某种**单调性**：比如数组元素全为正数，那么窗口越长，总和一定越大。这种确定性让我们敢于在满足条件时收缩左边界，而不担心错过最优解。

------

## 二、 滑动窗口能解决的题型

只要题目出现 **“子数组” (Subarray)** 或 **“子串” (Substring)**，且要求是 **“连续”** 的，你的第一反应就应该是滑动窗口。

### **1. 固定窗口大小**

题目给定了窗口的长度 K，求某个特征值。

- **典型题：** 子数组最大平均数、包含特定字符数量的定长子串。
- **技巧：** 先初始化第一个窗口，然后开始循环，每次 `sum += nums[right] - nums[left]`。

### **2. 变长窗口（寻找最短/最小）**

窗口大小不固定，目标是找到满足条件的**最短**区间。

- **典型题：** 长度最小的子数组（和大于等于 S）。
- **原理：** `right` 主动向右移，直到满足条件；然后 `left` 被动向右移，试图“榨干”水分，寻找极限最短长度。

### 3. 变长窗口（寻找最长）

窗口大小不固定，目标是找到满足条件的**最长**区间。

- **典型题：** 无重复字符的最长子串、最多替换 K 个元素后的最长连续 1。
- **原理：** `right` 不断向右扩充，一旦**违背**了题目条件（比如出现了重复字符），`left` 就开始收缩，直到重新满足条件为止。

------

## 三、 Java 实现模板（变长窗口）

这是最通用的模板，建议理解并背下来，大部分题只是在修改里面的 `condition`。

```
public int slidingWindow(int[] nums) {
    int left = 0, right = 0;
    int res = 0; // 或者 Integer.MAX_VALUE
    // 1. 维护窗口内的状态（如 sum, count, HashMap 等）
    int windowState = 0; 

    while (right < nums.length) {
        // 2. 【入窗】：把右边的元素加入窗口，更新状态
        windowState += nums[right];
        
        // 3. 【收缩】：判断是否需要移动左边界
        // 寻找最短时用 while，寻找最长时用 if（视题目而定）
        while (windowState >= target) { 
            // 4. 【更新答案】：在这里记录满足条件的解
            res = Math.min(res, right - left + 1);
            
            // 5. 【出窗】：把左边的元素移出窗口，更新状态
            windowState -= nums[left];
            left++;
        }
        right++;
    }
    return res;
}
```

------

## 四、 为什么滑动窗口在 Java 中很高效？

1. **对象复用：** 在处理字符串子串（Substring）时，如果你不停地调用 `s.substring(i, j)`，Java 会频繁创建新的字符串对象。而滑动窗口只操作索引（指针），**零对象创建**。
2. **容器配合：** Java 的 `HashMap` 或数组（作为频率表）在滑动窗口中非常强大。
   - 如果是处理 ASCII 字符，直接定义 `int[] map = new int[128];` 代替 `HashMap`，性能会起飞。
3. **防止冗余操作：** 像 `HashSet.contains()` 这种操作在窗口滑动过程中只需要增量进行，不需要每步重新扫描。

------

## 避坑指南

- **边界计算：** 窗口的长度是 `right - left + 1`，这个 `+1` 经常容易忘。
- **初始值设置：** 找最小长度时，初始值设为 `Integer.MAX_VALUE`；找最大长度时，设为 `0`。
- **收缩条件：** 想清楚是“满足条件时收缩”还是“违背条件时收缩”。

**对比一下：**

- **双指针（对撞）：** 是从两头往中间挤，主要是为了**排除**不可能的选项。
- **滑动窗口：** 是从左往右拉，主要是为了**捕获**一段连续的范围。

# 3. 前缀和 (Prefix Sum)

当你发现题目反复要求某个**区间范围内的和**时，就要想到前缀和。

- **核心思想：** 预处理一个数组 `preSum`，其中 `preSum[i]` 表示原数组前 i 个元素的总和。
- **公式：** 区间 [i, j] 的和 = preSum[j+1] - preSum[i]。这样可以将区间求和的时间复杂度从 O(n) 降到 O(1)。
- **适用场景：** 区域和检索、寻找数组的中心下标。

------

# 4. 排序 (Sorting)

很多数组题在无序状态下很难做，但一**排序**就豁然开朗。

- **思路：** 拿到题先问自己：如果数组是有序的，是不是就好办了？
- **适用场景：** 寻找重复元素、找出最接近的数、区间合并。
- **Java 工具：** `Arrays.sort(nums);` （内部使用的是优化的快速排序或归并排序）。

------

# 5. 空间换时间 (Hash Table)

如果你发现题目要求查找某个元素，或者统计出现频率。

- **核心思想：** 利用 `HashMap` 或 `HashSet`。
- **适用场景：** 两数之和（Two Sum）、判断是否存在重复元素。
- **Java 技巧：** * 统计频率：`map.put(num, map.getOrDefault(num, 0) + 1);`
  - 利用数组下标：如果题目限制了数值范围（比如都在 1 到 n 之间），你可以直接开一个大小为 n+1 的数组当做简化版的 HashMap 使用。

   - `Arrays.fill(nums, 0)`：快速填充初值。
