## 1. 三种数据交换方式：打电话 vs 寄包裹 vs 寄小件

### 电路交换（传统电话模式）

**原理**：像打电话，先拨号建立连接，独占一条线路，说完再挂。

**三个步骤**：

1. **建立连接**：拨号，占线（比如"您拨打的用户正在通话中"就是占线了）
2. **通话**：独占线路，比特流像水流一样直通
3. **释放连接**：挂电话，释放资源

**优点**：

- 延迟低且稳定（适合实时通话）
- 独占带宽，不会卡顿

**致命缺点**：

- **资源浪费**：即使双方不说话，线路也被占着（静默期浪费）
- **不适合电脑上网**：电脑上网是"突发式"的——疯狂下载10秒，然后停5分钟看网页，用电路交换太亏

**复用技术**（提高利用率）：

- **频分复用（FDM）**：把线路按频率切成多个"车道"，各走各的（像广播不同频道）
- **时分复用（TDM）**：把时间切成小片，大家轮流用（像红绿灯）

------

### 报文交换（整包寄送）

**原理**：像寄快递，整个文件打包成一个"报文"，快递员（路由器）先收完整包，再转发。

**特点**：

- **存储转发**：必须收完整包才能往下传
- **灵活**：不用提前建立连接，有路就走，没路就换
- **缺点**：包太大时，路由器缓存压力大；出错要重传整个包，效率低

------

### 分组交换（互联网的选择，寄小件模式）

**原理**：把大文件切成"小包裹"（分组），每个包裹贴上地址标签（首部），独立寄送，到目的地再拼起来。

**关键过程**：

1. **发送方**：切包→贴标签→发出
2. **路由器**：收包→存包→查地址→转发（存储转发）
3. **接收方**：收齐所有包→按序号拼回原文件

**为什么选这个？**

- **故障容错**：某条路断了，包自动绕路（像导航避开拥堵）
- **资源共享**：不同人的包可以挤在同一条线路上，谁有数据谁发
- **按需分配**：不用提前占线，有数据就发，没数据就给别人用

------

## 2. 分组交换的核心机制：存储转发

**存储转发**：路由器必须收完一个分组的所有比特，确认没问题，才能往下一站发。

**时间计算示例**：

- 分组大小：L 比特
- 网速：R bps（比特/秒）
- 传输时间（把包推上线路）：L/R 秒

**简单场景**（源→路由器→目的）：

- 源发完包到路由器：L/R 秒
- 路由器存完再发到目的：L/R 秒
- **总时延**：2L/R 秒

**多链路场景**（经过N条链路，N-1个路由器）：

- 一个包的总时延：N × (L/R)
- P个包流水线发送（像工厂流水线）：**(P + N - 1) × (L/R)**

**类比**：像多米诺骨牌，第一块倒到最后一块需要时间，但后面的牌可以紧接着倒，不用等前一批全倒完。
**注**：时延主要是看传输时延，即将数据塞进链路需要的时间。而数据在链路传播的时间几乎不需要考虑，因为是以光速传播，太快了。

------

## 3. 分组交换的问题：排队和丢包

### 排队时延（等红灯）

当多个包同时到达路由器，要抢同一条出路时：

- 路由器有个"输出缓存"（队列），像银行排队
- 先到先服务（FIFO），排队的等待时间就是**排队时延**
- 网络越堵，排队越长（看视频卡顿就是这个原因）

### 分组丢失（仓库满了）

如果排队太长，缓存满了：

- 新来的包没地方存，直接扔掉（**丢包**）
- 需要发送方重传（像快递丢了重新寄）

## 4. 路由器怎么知道往哪发？转发表和路由协议

### 转发表（导航手册）

- 路由器内部有张表，记录"目的IP前缀→出接口"
- 例如：目的地址是192.168.1.x，就走2号口

### 路由选择协议（自动更新地图）

- 不是人工配置的！路由器之间自动"聊天"（协议），实时更新最优路径
- 功能：
  1. **发现路径**：探测网络拓扑（哪条路通、哪条路断）
  2. **算最优路**：用算法（如Dijkstra最短路径）找最快路线，像高德地图实时导航

## 5. 电路交换 vs 分组交换：终极PK



| 对比项       | 电路交换（电话）   | 分组交换（互联网）     |
| :----------- | :----------------- | :--------------------- |
| **资源占用** | 独占，静默期浪费   | 共享，谁用谁占         |
| **建立连接** | 需要（拨号等待）   | 不需要（即发即走）     |
| **延迟**     | 低且稳定           | 可能有排队延迟，不稳定 |
| **适合场景** | 实时通话、视频会议 | 网页、文件、视频流     |
| **成本**     | 高（预留资源）     | 低（按需分配）         |
| **灵活性**   | 差（线路固定）     | 强（自动绕路）         |

### 数学对比（关键！）

**场景**：1Mbps链路，35个用户，每人活跃时100kbps，但只活跃10%时间。

- **电路交换**：每人独占100kbps → 只能支持 **10人**（1M/100k），第11人打不通。
- **分组交换**：
  - 35人同时活跃的概率极低（0.04%）
  - 99.96%时间 ≤10人活跃 → 不排队
  - **支持35人**，利用率提升3.5倍！

**突发流量对比**：

- 1个用户突发传1000个包，电路交换（TDM）要1000秒（轮流用时隙）
- 分组交换只要1秒（独占带宽）

------

## 6. 现代融合：不是非黑即白

虽然互联网主要是分组交换，但**电路交换的思想还在**：

- **5G QoS**：给视频通话预留带宽（类似电路交换），同时让普通上网用分组交换
- **技术融合**：用统计时分复用（STDM）、波分复用（WDM）提高电路交换效率

------

## 一句话总结

**电路交换像"包场"（独占但浪费），分组交换像"拼桌"（共享但可能排队）。互联网选分组交换是因为电脑上网"一阵一阵"的，拼桌最划算；但打电话、视频会议等对延迟敏感的场景，还是需要"包场"的稳定性。现代网络是两者结合！**
