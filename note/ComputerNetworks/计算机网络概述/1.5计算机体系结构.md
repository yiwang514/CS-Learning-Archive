## 1. 为什么要分层？（核心思想）

网络太复杂了，一次性搞不定，所以**把大问题拆成小问题**，每层只干一件事。

**分层的好处**：

- **简化设计**：每层只关心自己的活，不用管别的层怎么实现（像工厂流水线）
- **标准化**：每层独立定规矩，比如传输层用TCP还是UDP，不影响上层应用
- **灵活替换**：WiFi换5G，只要接口一样，上层应用无感知（像换电池不用换手机）

**类比**：寄快递

- 你（应用层）：写好信，装信封
- 快递公司（传输层）：打包、贴单号、保证送达
- 物流公司（网络层）：规划路线，从北京到上海
- 司机（数据链路层）：开车走高速
- 公路（物理层）：沥青路、水泥路

每层只和上下层打交道，不用关心别的层怎么干。

## 2. 三种常见网络模型

| 模型               | 层数 | 特点                         |
| :----------------- | :--- | :--------------------------- |
| **OSI七层模型**    | 7层  | 理论完整，学术用，实际没落地 |
| **TCP/IP四层模型** | 4层  | 实际互联网用的，实用主义     |
| **五层教学模型**   | 5层  | 折中方案，教学常用，好理解   |

**五层模型（最常用）**：

1. **应用层**：直接为用户服务（微信、浏览器、邮件）
2. **传输层**：端到端可靠传输（TCP保证不丢包，UDP快但不保证）
3. **网络层**：找路、选路由（IP地址、路由器）
4. **数据链路层**：相邻节点传数据（MAC地址、交换机、以太网）
5. **物理层**：比特流变电信号/光信号（网线、光纤、WiFi频段）

**TCP/IP实际四层**（把数据链路层和物理层合并为"网络接口层"）：

- 应用层、传输层、网际层（IP层）、网络接口层

## 3. 每层解决的核心问题

| 层次           | 解决的核心问题               | 关键词                 |
| :------------- | :--------------------------- | :--------------------- |
| **应用层**     | 满足特定应用需求             | HTTP、DNS、SMTP        |
| **传输层**     | 进程到进程的通信，可靠或快速 | 端口、TCP/UDP          |
| **网络层**     | 跨网络找路径，逻辑寻址       | IP地址、路由、分组转发 |
| **数据链路层** | 相邻节点可靠传输，物理寻址   | MAC地址、帧、差错检测  |
| **物理层**     | 比特怎么变信号               | 电压、光脉冲、无线频段 |

## 4. 层与层之间怎么交互？（关键概念）

### 实体（Entity）

- 任何能发/收信息的硬件或软件进程
- **对等实体**：通信双方同一层的实体（比如你的浏览器和网站服务器都是应用层实体）

### 协议（Protocol）——"水平"的

- **控制对等实体之间通信的规则集合**
- 只有对等实体之间才有协议（比如传输层和传输层对话用TCP，和网络层不叫协议）

### 服务（Service）——"垂直"的

- **下层为上层提供的功能**
- 上层使用下层的服务，但**不知道下层怎么实现的**（透明性）
- 就像你用WiFi上网，不用知道路由器里面怎么跑的路由协议

### 服务访问点（SAP）

- 上下层交换信息的"接口"
- 不同层的SAP：
  - 数据链路层：帧的"类型"字段（区分是IP数据还是ARP）
  - 网络层：IP数据报的"协议"字段（区分是TCP还是UDP）
  - 传输层："端口号"（区分是微信还是浏览器）

### 服务原语

- 上层调用下层服务的"命令"
- 比如：应用层说"给我建立TCP连接"，传输层就开始干活

## 5. 数据怎么打包？（PDU、SDU、PCI）

**关键概念**：

- **SDU（服务数据单元）**：上层交给我的原始数据
- **PCI（协议控制信息）**：本层加的"控制头"（地址、序号、校验等）
- **PDU（协议数据单元）**：PCI + SDU = 本层的完整数据包

**封装过程（像俄罗斯套娃）**：

```plain
应用层数据（APDU）
↓ + 传输层头部（PCI）= 段/报文（TPDU）
↓ + 网络层头部（PCI）= 分组/包（NPDU，即IP数据报）
↓ + 数据链路层头部+尾部（PCI）= 帧（DPDU）
↓ + 物理层编码 = 比特流（电信号/光信号）
```

**解封装**：接收方一层层剥掉头部，把数据交给上层。

## 6. 实际例子：访问网页时数据怎么流动

### 发送方（你的电脑）：

1. **应用层**：浏览器生成HTTP请求（"我要看www.baidu.com"）
2. **传输层**：加TCP头部（源端口、目的端口80、序号），变成TCP段
3. **网络层**：加IP头部（你的IP、百度服务器IP），变成IP数据报
4. **数据链路层**：加MAC头部（你的网卡MAC、路由器MAC）、尾部校验，变成帧
5. **物理层**：帧变成电信号/光信号，发出去

### 中间节点（路由器）：

- **物理层**：收信号，还原成比特
- **数据链路层**：检查帧没错，剥掉MAC头部
- **网络层**：查IP地址，看路由表，决定下一跳；加新的MAC头部（下一跳的MAC）
- **物理层**：再发出去

**注意**：路由器只处理到网络层，不碰传输层和应用层！

### 接收方（百度服务器）：

1. **物理层**：收信号
2. **数据链路层**：剥MAC头部，检查
3. **网络层**：剥IP头部，检查
4. **传输层**：剥TCP头部，按序号排好，保证不丢包
5. **应用层**：HTTP请求交给Web服务器软件，生成网页内容

### 响应回去：

服务器把网页内容按同样流程封装，发回给你，你的电脑再一层层解封装，浏览器显示网页。

------

## 一句话总结

**分层就像寄快递：每层只干自己的活，通过"加头"封装数据，对等层通过协议对话，上下层通过服务接口交互。你的数据从应用层往下层层打包，到对端再层层拆包，中间路由器只拆到网络层看地址。这种设计让网络灵活、标准、好维护！**
