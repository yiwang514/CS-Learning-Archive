1.联表查询：
    核心课本概念
        外键（Foreign Key）：那个用来跨表寻人的桥梁。在成绩表中，学号 就是指向学生表的主键的“外键”。它宣示了两个表之间的关联性。
        连接条件（ON）：告诉数据库，按照什么规则把两张表缝合起来。在上面的例子里，规则就是：学生表.学号 = 成绩表.学号。
    联表查询的三大流派
    1. 截取交集：内连接（INNER JOIN）
        现实态度：“门当户对，双向奔赴。只有两边都匹配上的才展示，落单的一律抛弃！”
        校园表现：只展示既在花名册上、又确实参加了考试的学生成绩。没考过试的同学直接忽略，幽灵成绩也直接扔掉。
        默认设定：在 SQL 里，如果你只写 JOIN 不加修饰词，默认就是 INNER JOIN。

    2. 以左为主：左连接（LEFT JOIN / LEFT OUTER JOIN）
        现实态度：“以左边这张表为核心，左边的人一个都不能少！右边匹配不上的，填个空白（NULL）也要把左边的人保住。”
        校园表现：校长说：“我要看全校所有学生的考试情况！”这就必须用 LEFT JOIN。
        即使小明因为生病缺考了任何科目（右边的成绩表里没有他），他的名字依然会神气地出现在报告纸上，只不过分数那一栏会被数据库用 NULL（空值）填充。

    3. 以右为主：右连接（RIGHT JOIN / RIGHT OUTER JOIN）
        现实态度：“以右边这张表为核心，右边有一行算一行。左边匹配不上，左侧填空值。”
        校园表现：逻辑与左连接完全相反，实际开发中为了阅读习惯，大部分程序员都能用 LEFT JOIN 就不用 RIGHT JOIN（只需要把两张表在 SQL 里的位置互换一下即可）。



2.  Q：join和on的执行顺序是在WHERE前还是后？
    A： 【第 1 步】 FROM      --> 锁定左表（搬出第一张表）
        【第 2 步】 ON        --> 确立两表的缝合规则（订书机对齐规则）
        【第 3 步】 JOIN      --> 引入右表并完成生成临时合并表（钉成大表）
        【第 4 步】 WHERE     --> 门卫大爷登场！对缝合好的大表进行条件初筛

3.  Q：既然 ON 和 WHERE 都有“过滤筛选”的意思，为什么 ON 必须在 WHERE 前面？
    A： 在内连接（INNER JOIN）中，两者确实没区别，因为内连接只留交集。
        但在左连接（LEFT JOIN）中，两者的差别极其致命
        ON 的阶段（建表时）：它的任务是决定右边的表该怎么拼过来。如果右表匹配不上（比如小明缺考了高数），在 LEFT JOIN 的“左表为主”铁律下，数据库会说：“虽然你没考，但为了保住左边的学籍，我用 NULL（空值）给你填上。”此时小明还活着。
        WHERE的阶段（表建好后）：它是对那张已经拼好的“临时大表”进行无差别屠杀。如果你的条件写在  WHERE 里（比如 WHERE 分数 > 60），门卫大爷看到小明的分数是 NULL，直接就说：“这不是大于 60，给我扔掉！”此时，小明连同他左表的学籍记录，全部被干掉了。

        在使用 LEFT JOIN 时：
            如果是对【右表（附表）】进行条件过滤，且希望能保留左表独活的数据，条件必须全部写在 ON 后面！
            只有当你真想“毁灭全行”，对【左表（主表）】自身进行初筛时（比如“我只要一班的学生”），才把条件写在 WHERE 后面。

4.  一个误区：
        一个表主键只能有一个，但主键却不是只能包含一个数据表字段。
        可以由多个字段构成————复合（联合）主键
        想象大学里的选课系统：
        单独看“学号”：一个学生可以选多门课，学号会重复（不唯一）。
        单独看“课程号”：一门课有多个学生选，课程号也会重复（不唯一）。
        但 “学号 + 课程号”组合在一起：一个学生不可能对同一门课选两次，这个组合是唯一的！
        所以选课表的主键就是 (student_id, course_id) —— 两个字段联手才能唯一锁定一行。


5.  Q:  ALTER TABLE 表名 DROP KEY/INDEX 约束名称，为啥DROP后面跟着的是KEY/  INDEX？
    A:  因为在 MySQL 的底层世界观里，UNIQUE（唯一约束）本质上就是一个“带了唯一性检查的索引”，而 KEY 就是 INDEX（索引）的别名。删唯一约束 = 删索引，所以用 DROP KEY（或 DROP INDEX）。
