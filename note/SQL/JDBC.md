1.  Q:为啥课本教Statement而ai教我用PreparedStatement？
    A：用奶茶店后厨的例子来打比方，你要给后厨下达做菜指令，有两种方式：

    1. Statement（旧时代的“纯手写纸条”）
教程为什么爱教它：因为它最简单直接。你只需要把 SQL 语句像拼积木一样拼成一个完整的字符串，比如："SELECT * FROM users WHERE name = '" + userName + "'"，然后直接扔给数据库执行。

它致命的物理缺陷（SQL 注入）：因为是纯字符串拼接，如果有个黑客顾客，故意把自己的名字注册为 ' OR '1'='1。
你的代码一拼接，发给数据库的指令就变成了：SELECT * FROM users WHERE name = '' OR '1'='1'。
数据库一看：“1永远等于1，条件成立！”然后当场把全公司所有用户的密码全查出来发给了黑客！在工业界，用 Statement 拼接字符串是绝对的零容忍红线。

    2. PreparedStatement（现代工业的“填空题模版”）
它的底层防御机制：它是 Statement 的进化版（在 Java 源码里，它直接继承了 Statement）。你不再拼接字符串了，而是给后厨发一张提前印刷好的“填空题模版”：
"SELECT * FROM users WHERE name = ?"
数据库收到模版后，会先进行语法编译和死锁。然后你再把黑客的名字填进 ? 里。这个时候，就算黑客填了 ' OR '1'='1，数据库也只会把它当成一个“名字叫这个长串的奇怪客人”，而绝对不会把它当成 SQL 逻辑去执行！

结论：课本教 Statement 是为了让你懂最原始的原理；但在真实工作中，我们 100% 只用带 ? 号的 PreparedStatement。







2.  四大api的基本函数：
四大 API 的底层核心函数拆解

现在我们抛开 Java 复杂的语法，只看这四大 API 中**最关键的几个动词（函数/方法）**，看看它们到底是如何完成物理交互的。

### 1. `DriverManager`（通信局的接线总机）

它是一个管理工具，它的唯一历史使命就是“帮你接通电话线”。

* **核心函数**：`getConnection(网址, 账号, 密码)`
* **底层物理动作**：它会通过底层 TCP/IP 协议，向远端的 MySQL 服务器发送握手请求。如果账号密码验证通过，它就会返回一根极其宝贵的“物理网线（Connection）”给你。

### 2. `Connection`（你和数据库之间的物理专线）

这根专线建立起来极其耗时（要经过网络三次握手等底层操作），所以拿到了就要好好用。

* **核心函数 1**：`createStatement()` -> 给你生成一张空白的 `Statement` 手写纸条。
* **核心函数 2**：`prepareStatement(SQL模版)` -> 给你生成一张带 `?` 号的 `PreparedStatement` 填空题纸条，同时立刻把模版发给数据库预编译。
* **核心函数 3**：`close()` -> **极其重要！** 挂断电话，断开 TCP 网络连接。如果不关，数据库的连接池很快就会被占满，整个系统直接死机。

### 3. `Statement` / `PreparedStatement`（执行 SQL 的发射器）

拿到了纸条，填好了字，现在要把它发射给数据库了。这里有两种截然不同的发射按钮：

* **核心函数 1**：`executeQuery()` （翻译：执行查询）
* **适用场景**：只用来执行 `SELECT` 语句。
* **底层物理动作**：数据库去硬盘里翻找数据，然后打包装进一个叫 `ResultSet` 的大盒子里返回给你。


* **核心函数 2**：`executeUpdate()` （翻译：执行更新）
* **适用场景**：用来执行 `INSERT`（增）、`UPDATE`（改）、`DELETE`（删）。
* **底层物理动作**：数据库直接去修改物理硬盘上的数据，它不会返回表格，而是**返回一个整数（int）**，告诉你“有几行数据被成功修改了”。



### 4. `ResultSet`（装满数据的快递餐盒）

当你执行了 `SELECT` 查询后，拿到的 `ResultSet` 不是一个可以直接打印的普通数组，它在底层其实是一个**游标（Cursor / 指针）**。

* **核心函数 1**：`next()`
* **底层物理动作**：刚拿到盒子时，指针停在第一行数据的**上方**（啥也读不到）。你调用一次 `next()`，指针就“咔哒”往下走一行。如果这一行有数据，它返回 `true`；如果已经走到底了（没数据了），它返回 `false`。这就为什么我们总是用 `while (rs.next())` 循环来读取。


* **核心函数 2**：`getInt("列名")` / `getString("列名")` / `getDouble("列名")`
* **底层物理动作**：当指针停在某一行时，你用这些函数，精准地把这一行里某一列的数据抓取出来，转换成 Java 认识的 int 或 String 类型。



---

用最精简的逻辑串起来就是：
`DriverManager` 帮你拨通 **`Connection` (专线)** $\rightarrow$ 你拿着专线向数据库要一张 **`PreparedStatement` (填空纸)** $\rightarrow$ 填好后按下 **`executeQuery` (发射键)** $\rightarrow$ 收到 **`ResultSet` (装数据的盒子)** $\rightarrow$ 用 **`next` (指针)** 一行行读取。








3.  JDBC的操作流程

很多新手看教程时，看到代码最上面写着 `import java.sql.Connection;`，就以为这就是“引入驱动包”了，结果一运行直接报 `ClassNotFoundException`（找不到类）。

我们用最直白的方式，先把这个“引入驱动包”的物理动作搞明白，然后再把 JDBC 的完整步骤串一遍。

---

## 第一阶段：什么是驱动包？到底怎么引入？

**本质区别：**

* **代码里的 `import java.sql.***`：这只是拿出了 Java 官方自带的“标准对讲机图纸”。
* **引入驱动包（.jar 文件）**：这是你去 MySQL 官网下载了一个真实的“翻译官”（一个后缀为 `.jar` 的压缩包，里面装满了 MySQL 官方写好的底层代码），并**把它物理塞进你的 Java 项目里**。

目前在 Java 开发中，引入这个 `.jar` 包有两种主流方式：

### 方式一：现代工业标准做法（使用 Maven 构建工具）

如果你使用的是相对现代的教程或项目，99% 都在用 Maven。Maven 就像是 Java 的“全自动应用商店”。
你完全不需要自己去下载文件，只需要在项目根目录的 `pom.xml` 文件里，写上一张“购物清单”（依赖配置）：

```xml
<!-- 在 pom.xml 的 <dependencies> 标签里加上这段 -->
<dependency>
    <groupId>mysql</groupId>
    <artifactId>mysql-connector-java</artifactId>
    <version>8.0.33</version> <!-- 根据你的 MySQL 版本选择 -->
</dependency>

```

**底层动作**：只要你保存这个文件，IDEA 等开发工具就会自动联网，去全球中央仓库把 MySQL 的翻译官 `.jar` 包下载下来，并无缝接入到你的项目中。

### 方式二：传统手工做法（纯手动导包）

如果你建的是一个最原始的 Java SE 项目（没有用到 Maven），你就得“手工搬砖”了：

1. **下载**：去网上（比如 Maven 中央仓库或者 MySQL 官网）下载一个名叫 `mysql-connector-java-8.0.33.jar` 的文件。
2. **放进项目**：在你的 IDEA 项目文件夹里，新建一个名叫 `lib` 的文件夹，把这个 `.jar` 文件复制进去。
3. **告诉 IDEA（最关键一步）**：对着这个 `.jar` 文件点击**鼠标右键**，在弹出的菜单里找到并点击 **Add as Library...（添加为库）**。
**底层动作**：此时 IDEA 会把这个文件解析进你的项目环境里。只有做了这一步，你的代码在运行时才能真正找到 MySQL 的底层实现类。

---

## 第二阶段：JDBC 详细操作六步曲（带代码级解析）

翻译官（驱动包）物理入驻项目后，我们就可以严格按照 JDBC 的规章制度开始打电话了。

### 第 1 步：注册驱动（叫醒翻译官）

你需要让 Java 知道你打算用哪家的驱动。

```java
// 告诉 Java，把 MySQL 的翻译官叫醒，准备干活。
Class.forName("com.mysql.cj.jdbc.Driver"); 

```

> **行业冷知识**：从 JDBC 4.0 版本（Java 6）开始，只要你把 `.jar` 包按上面教的方法放进了项目里，Java 就会**自动**叫醒翻译官，所以现代开发中这一行代码其实是可以省略不写的！但很多老教程依然保留了它。

### 第 2 步：获取数据库连接（拉起物理专线）

这是极其耗费系统资源的一步，相当于跨城市架设了一根专属光缆。

```java
// 三个参数：数据库地址(url)、用户名、密码
String url = "jdbc:mysql://127.0.0.1:3306/你的数据库名?useSSL=false&serverTimezone=UTC";
Connection conn = DriverManager.getConnection(url, "root", "123456");

```

### 第 3 步：创建执行 SQL 的对象（准备预编译派单纸）

绝不要用原始的拼接字符串，一律使用带问号的 `PreparedStatement`。

```java
// 把带有 ? 号的模版提前发给数据库，让它做好防黑客的安全检查
String sql = "SELECT * FROM users WHERE age > ? AND department = ?";
PreparedStatement pstmt = conn.prepareStatement(sql);

```

### 第 4 步：设置参数并执行（填空并按下发射键）

根据你上面写的问号顺序（从 1 开始排），把真实数据填进去。

```java
// 给第 1 个问号填上数字 18
pstmt.setInt(1, 18); 
// 给第 2 个问号填上字符串 "市场部"
pstmt.setString(2, "市场部"); 

// 发射执行！因为是 SELECT 语句，所以用 executeQuery()，它会返回一个结果集
ResultSet rs = pstmt.executeQuery(); 

```

### 第 5 步：处理结果集（拆快递盒）

后厨把查到的数据装在 `ResultSet` 盒子里送回来了，我们需要用循环一行行把数据拿出来。

```java
// rs.next() 像游标一样，往下走一行，如果有数据就进循环
while(rs.next()) {
    // 假设表里有一列叫 "username"
    String name = rs.getString("username"); 
    // 假设表里有一列叫 "salary"
    double salary = rs.getDouble("salary"); 
    
    System.out.println(name + " 的工资是: " + salary);
}

```

### 第 6 步：释放资源（过河拆桥，强制挂断）

数据库服务器能同时维持的专线数量是有限的（可能只有 100 根）。你打完电话如果不主动挂断，占着茅坑不拉屎，后面的用户就全卡死了。

```java
// 必须在 finally 代码块中执行，且顺序必须与打开的顺序相反（先开后关）
if (rs != null) rs.close();
if (pstmt != null) pstmt.close();
if (conn != null) conn.close();

```







4.  Q:实例里的数据库地址（URL）也太奇怪了？看不太懂？
    A:
    这个问题问得太接地气了！无数新手在学完 JDBC 的各种高大上理论后，一坐在电脑前，对着 `String url = ???` 这行代码就开始发呆。

代码写得再溜，如果不知道“后厨的具体地理位置”，电话也是打不通的。

这个所谓的“数据库地址（URL）”，其实就像你往快递单上填写的“省市区 + 街道门牌号 + 具体的收件人”。我们来把它彻底拆解，教你如何精准定位你的数据库。

---

## 🔍 第一阶段：拆解快递单（JDBC URL 的物理结构）

一个标准的 MySQL 数据库地址通常长这样：
`jdbc:mysql://127.0.0.1:3306/milktea_shop?useSSL=false&characterEncoding=utf8`

别看它长得像一堆乱码，其实它被严格划分成了四个区域。我们用一张表来看透它的物理结构：

| 组成部分 | 真实代码 | 现实含义 | 怎么确认你的填啥？ |
| --- | --- | --- | --- |
| **协议类型** | `jdbc:mysql://` | **对讲机频道**。告诉 Java 接下来要用 MySQL 的方言来通讯。 | **死记硬背**。只要你连的是 MySQL，这段前缀永远不改。 |
| **IP 地址** | `127.0.0.1` (或 `localhost`) | **大楼地址**。数据库所在的电脑到底在地球上的哪个位置。 | 看第二阶段的具体排查方法。 |
| **端口号** | `:3306` | **房间门牌号**。一台电脑里有很多软件，3306 是 MySQL 默认包下的专属房间。 | 绝大多数情况都是 `3306`，除非你安装时自己手欠改了。 |
| **数据库名** | `/milktea_shop` | **具体找哪个人**。一个 MySQL 里可以建很多个独立的数据库。 | 就是你在命令行里敲 `CREATE DATABASE 库名;` 时的那个名字。 |
| **附加参数** | `?useSSL=false...` | **特别嘱咐**。比如“不要用加密通话（useSSL=false）”、“我们说中文（utf8）”。 | 连上问号 `?` 一起拼在最后，多个参数用 `&` 连接。 |

---

## 🛠️ 第二阶段：如何查出你的 IP 地址和端口？（对号入座）

你要找地址，完全取决于你的 MySQL 数据库**安装在了哪里**。请对照以下三种最常见的情况：

### 情况 1：数据库就装在你现在敲代码的这台电脑上（90% 初学者的状态）

* **大楼地址**：你的电脑就是大楼。在计算机网络里，有一个永远指向“自己”的特殊魔法地址，叫做 **`localhost`** 或者 **`127.0.0.1`**。
* **最终 URL 写法**：`jdbc:mysql://localhost:3306/你的数据库名`

### 情况 2：你买了一台云服务器（比如阿里云、腾讯云）

* **大楼地址**：你需要登录你的云服务器控制台，找到那台服务器的“公网 IP”（比如 `114.55.88.99`）。
* **最终 URL 写法**：`jdbc:mysql://114.55.88.99:3306/你的数据库名`
* **避坑指南**：云服务器默认有一道“防火墙（安全组）”。你必须在云平台的网页控制台里，手动把 `3306` 这个门牌号开放（允许入方向流量），否则你的 Java 代码死活连不上，会一直报 `Timeout` 超时错误。

### 情况 3：你在用图形化工具（如 Navicat、DataGrip）而且能连上

如果你平时能用 Navicat 连上数据库，但不知道填啥代码，你可以直接去“抄作业”！

* **操作动作**：在 Navicat 里右键点击你的数据库连接，选择“编辑连接（Edit Connection）”。
* **抄作业方法**：弹出的窗口里，清清楚楚地写着“主机（Host）”和“端口（Port）”。主机填到 `//` 后面，端口填到 `:` 后面，完美解决！

---

## 💡 终极避坑：URL 后面的“附加参数”必须要写吗？

在老版本的 MySQL（比如 5.7 及以前）里，你光写 `jdbc:mysql://localhost:3306/库名` 是可以连上的。
但在新版本（MySQL 8.0 以上）里，Java 的安检极其严格，如果你不加附加参数，大概率会遇到一堆红色的警告甚至报错。

**行业标准万能后缀套餐：**

```java
String url = "jdbc:mysql://127.0.0.1:3306/你的数据库名?useSSL=false&serverTimezone=Asia/Shanghai&characterEncoding=utf8";

```

* `useSSL=false`：告诉 Java，咱们在自己电脑上玩，不用搞极其复杂的 SSL 安全加密证书验证。
* `serverTimezone=Asia/Shanghai`：解决时区错乱的世纪难题。不写这个，你存进数据库的时间可能会比现实世界快/慢 8 个小时。
* `characterEncoding=utf8`：保证你用 Java 塞进去的中文“珍珠奶茶”，到数据库里不会变成一堆“?????”乱码。

把它当成一个固定的公式刻在你的代码模板里，你的 JDBC 就能畅通无阻地直达后厨了！
