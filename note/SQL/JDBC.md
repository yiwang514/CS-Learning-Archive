1.  Q:为啥课本教Statement而ai教我用PreparedStatement？
    A：用奶茶店后厨的例子来打比方，你要给后厨下达做菜指令，有两种方式：

    1. Statement（旧时代的“纯手写纸条”）
教程为什么爱教它：因为它最简单直接。你只需要把 SQL 语句像拼积木一样拼成一个完整的字符串，比如："SELECT * FROM users WHERE name = '" + userName + "'"，然后直接扔给数据库执行。

它致命的物理缺陷（SQL 注入）：因为是纯字符串拼接，如果有个黑客顾客，故意把自己的名字注册为 ' OR '1'='1。
你的代码一拼接，发给数据库的指令就变成了：SELECT * FROM users WHERE name = '' OR '1'='1'。
数据库一看：“1永远等于1，条件成立！”然后当场把全公司所有用户的密码全查出来发给了黑客！在工业界，用 Statement 拼接字符串是绝对的零容忍红线。

    2. PreparedStatement（现代工业的“填空题模版”）
它的底层防御机制：它是 Statement 的进化版（在 Java 源码里，它直接继承了 Statement）。你不再拼接字符串了，而是给后厨发一张提前印刷好的“填空题模版”：
"SELECT * FROM users WHERE name = ?"
数据库收到模版后，会先进行语法编译和死锁。然后你再把黑客的名字填进 ? 里。这个时候，就算黑客填了 ' OR '1'='1，数据库也只会把它当成一个“名字叫这个长串的奇怪客人”，而绝对不会把它当成 SQL 逻辑去执行！

结论：课本教 Statement 是为了让你懂最原始的原理；但在真实工作中，我们 100% 只用带 ? 号的 PreparedStatement。
