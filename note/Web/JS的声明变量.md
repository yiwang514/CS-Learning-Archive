**JS**中**声明变量**的关键词变成了**let**和**const**！现代 JavaScript 开发中，**默认使用 `let`来声明变量**。当你需要一个值后续会被改变的变量时，就用它。如果你需要一个不会被重新赋值的变量，则使用 `const`。

------

### 那为什么JS不用像c或Java那样定义int或是 String等等类型?

简单说，这是 **“动态弱类型”** 与 **“静态强类型”** 两种类型系统的差异。JavaScript属于前者，而C/Java属于后者。

**1. 核心差异：类型与变量的绑定时机**

- 

  **C/Java (静态类型)**：类型在**编译时**就确定，并与变量**牢牢绑定**。

  - 

    `int a = 10;`—— 你告诉编译器：`a`这个“盒子”**永远且只能**装整数。如果你试图写 `a = "hello";`，**编译器会直接报错**，阻止程序运行。这能在最早阶段避免大量类型错误，但也失去了灵活性。

- 

  **JavaScript (动态类型)**：类型在**运行时**确定，并与**值**绑定，而不是变量。

  - 

    `let a = 10;`—— 你只是创建了一个叫 `a`的“标签”。现在它贴在数字 `10`上。下一行你可以写 `a = "hello";`—— 这个“标签”可以轻松撕下来，贴到字符串 `"hello"`上。**这是完全合法的**。解释器在运行到每一行时，才知道当前变量里是什么类型。

**2. JavaScript这样设计的历史原因与优势**

JavaScript最初被创造出来，是为了在浏览器中编写一些简单脚本（比如表单验证），它的目标是：

- 

  **易学易用**：对初学者友好，不需要复杂的类型声明，可以快速写出能跑起来的代码。

- 

  **灵活快速**：非常适合处理来自网页（HTML表单、用户输入）的各种不确定类型的数据。一个变量可以先存数字，再存字符串，再存对象，非常自由。

- 

  **解释执行**：它是逐行解释执行的脚本语言，没有“编译”这个步骤，所以也无法在运行前做严格的类型检查。

**3. 这种设计带来的挑战与解决方案**

随着JavaScript项目变得无比庞大和复杂（比如整个Facebook前端），动态类型的缺点也暴露出来：

- 

  **难以维护**：你无法一眼看出一个变量应该是什么类型，容易写错。

- 

  **隐藏的Bug**：比如一个本该是数字的变量，不小心被赋了字符串，可能导致奇怪的错误，而且这种错误要到运行时才会暴露。

**因此，JavaScript社区发展出了强大的解决方案：TypeScript**

**TypeScript 可以看作是 JavaScript 的一个“超集”或“升级版”**。它完全兼容 JavaScript 的语法，但**加入了静态类型定义**，就像你熟悉的C/Java那样：

```typescript
// TypeScript 代码
let count: number = 10; // 明确声明count是数字类型
count = "hello"; // ❌ 这里TypeScript编译器会立刻报错，提示类型不匹配！

function greet(name: string): string { // 明确声明参数和返回值的类型
  return `Hello, ${name}`;
}
greet(123); // ❌ 报错，参数必须是字符串
```

**你用TypeScript写代码，它会进行严格的静态类型检查，提前发现错误。写完后，再通过一个编译器把它转换成普通的JavaScript去运行。**

**总结一下：**

| 特性             | C / Java         | JavaScript       | TypeScript (JS的进化)        |
| ---------------- | ---------------- | ---------------- | ---------------------------- |
| **类型系统**     | 静态强类型       | 动态弱类型       | **静态强类型**（编译时检查） |
| **类型检查时机** | 编译时           | 运行时           | 编译时                       |
| **变量与类型**   | 绑定             | 分离             | 绑定                         |
| **设计目标**     | 安全、高效、清晰 | 灵活、简单、快速 | **安全、可维护、且灵活**     |
